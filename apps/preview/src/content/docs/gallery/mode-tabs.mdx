Rows rather than tabs, so every mode is visible at once and the argument (the same field
grows with you) can be seen. Each mode names a slot; the page writes a fenced block into that
slot and gets the docs' highlighting.

## Props

| Prop    | Type              | What it does                        |
| ------- | ----------------- | ----------------------------------- |
| `modes` | `readonly Mode[]` | The rows, in order, numbered from 1 |

`Mode` is `{ name, slot, summary }`. `slot` names the slot whose content becomes that
mode's code pane; any slot name works, and a missing one renders an empty pane rather than
failing.
