ts-extended-errors is 1.0. The API that shipped through 0.x is now stable: `ExtendedError`,
`defineError`, the cause-chain helpers, `serializeError`, `deserializeError`, `toError`,
`isErrorLike`, `describeValue` and the exported types. From here, a breaking change to any of them,
to the serialized shape, or to the defaults of `toJSON` and `serializeError` means a new major.

The one breaking change is the runtime floor: Node.js 22.12 or newer. The library uses no Node.js
APIs, so browsers and other runtimes are unaffected.

1.0 also types `code` as the literal a class declares, so a `switch` over a taxonomy's codes can be
exhaustive; accepts an `interface` as a `context` type; and keeps a numeric `code` through a JSON
round trip.
